# STT_LOCAL 설계: 화자 식별 회의록 파이프라인

작성일: 2026-09-02

## 목표

클로바노트의 음성기록(화자별 전사문)을 로컬 diarization + OpenAI STT로 대체한다.
혼자 CLI로 쓴다. 산출물은 `[HH:MM:SS] 실명: 텍스트` 형식의 전사문이다.

범위 밖: LLM 요약, 웹 UI, 팀 배포, 실시간 처리.

## 사용 조건

- 녹음 환경은 회의실과 온라인이 섞여 있고 불규칙하다.
- 회의별 참석자 명단은 입력하지 않는다.
- 성문 DB 등록자 10~30명, 회의당 참석자 3~8명.

## 확인된 기술 사실 (2026-09-02 기준)

- pyannote.audio 4.x `Pipeline("pyannote/speaker-diarization-community-1")` 출력 `DiarizeOutput`은
  `speaker_diarization`, `exclusive_speaker_diarization`, `speaker_embeddings`(화자별 centroid,
  `speaker_diarization.labels()` 순서)를 돌려준다. 임베딩 모델은 WeSpeaker.
- pyannote 4는 torchcodec 기반이라 ffmpeg가 필수다. HF 토큰과 community-1 약관 동의가 필요하다.
- OpenAI `gpt-transcribe`(2026-07)는 `prompt`, `keywords`, `languages`를 지원하고 타임스탬프는 미지원.
  파일 25MB 제한, 분당 $0.0045. 타임스탬프는 diarization에서 얻으므로 구간별 슬라이싱이 유일한 경로다.
- `gpt-4o-transcribe-diarize`의 known speaker는 최대 4명이라 이 설계에 쓰지 않는다.

## 구조

```
STT_LOCAL/
  pyproject.toml
  stt_local/
    common.py      # diarize(), slice_wav(), 성문 DB load/save/match
    enroll.py      # 파이프라인 1
    transcribe.py  # 파이프라인 2
  test_stt_local.py
  voiceprints/     # 성문 DB (아래 참조)
  docs/superpowers/specs/
```

의존성: `pyannote.audio>=4`, `openai`, 시스템 ffmpeg. 그 외 추가하지 않는다.
numpy, scipy는 pyannote가 끌고 온다.

## 성문 DB 형식

```
voiceprints/
  홍길동.npy     # float32, shape (세션 수, 임베딩 차원). 세션마다 행 추가
  김철수.npy
  model.txt      # 임베딩 모델 식별자 한 줄
```

- 평균 벡터 하나가 아니라 세션별 centroid를 행으로 쌓는다. 혼합 환경의 마이크/방 조건별 벡터가 축적된다.
- 사람 점수 = 그 사람 행들과의 코사인 유사도 최댓값. 벡터는 저장 전 L2 정규화한다.
- `model.txt`의 값이 현재 파이프라인 임베딩 모델과 다르면 경고하고 종료한다.

## 파이프라인 1: enroll

```
python -m stt_local.enroll 회의.m4a --out enroll_out/ [--num-speakers 5]
python -m stt_local.enroll --commit enroll_out/
```

1단계 (추출)
- diarization을 돌린다. 화자 수는 기본 자동 추정이고 `--num-speakers`로 강제할 수 있다. (스파이크 결과 6: 자동이 더 정확했다)
- 클러스터마다 exclusive 구간 중 가장 긴 6개를 16kHz mono WAV로 저장한다.
  경로: `enroll_out/SPEAKER_00/1_0132-0141.wav` (순번_시작초-끝초).
- 같은 폴더에 pyannote가 준 centroid를 `centroid.npy`로 저장한다.
- 클립은 청취 전용이다. 클립에서 임베딩을 다시 계산하지 않는다.

수동 단계
- 사용자가 클립을 듣고 폴더명을 실명으로 바꾼다. 섞인 클러스터는 그대로 둔다.

2단계 (--commit)
- 이름이 `SPEAKER_`로 시작하지 않는 폴더만 골라 `centroid.npy`를 `voiceprints/<이름>.npy`에 행으로 추가한다.
- 같은 enroll_out을 두 번 commit하면 중복 행이 생긴다. 막지 않는다. (ponytail: 사용자가 안 그러면 됨)

## 파이프라인 2: transcribe

```
python -m stt_local.transcribe 회의.m4a --out out/0902회의/ \
  [--min-speakers 2 --max-speakers 10] [--threshold T] [--keywords "용어,제품명"]
```

1. diarize
   - 화자 수는 `min_speakers`/`max_speakers` 범위로 모델에 맡긴다. 기본 2~10. (자동 추정 품질은 스파이크 결과 6 참조)
   - exclusive 구간과 centroid를 받아 `out/diarization.json`과 `out/centroids.npy`에 저장한다.
   - 두 파일이 이미 있으면 diarization을 건너뛰고 읽는다. 재실행 때 클러스터 라벨이 바뀌면
     사용자가 고친 `speakers.json`이 어긋나므로, 이 캐시는 속도가 아니라 정합성을 위한 것이다.

2. match
   - 클러스터마다 독립적으로 가장 유사한 등록자를 고른다(argmax). 여러 클러스터가 같은 사람에게 붙어도 된다.
     스파이크에서 한 사람이 2~3개 클러스터로 갈라지는 일이 흔했고, 헝가리안 1:1은 이때 오배정을 냈다.
   - 유사도가 `threshold` 미만이면 `Unknown-1`, `Unknown-2`…로 둔다.
   - 결과를 `out/speakers.json`에 쓴다. `minutes`는 그 클러스터의 발화 시간이다:
     `{"SPEAKER_00": {"name": "홍길동", "score": 0.71, "minutes": 14.2}, "SPEAKER_01": {"name": "Unknown-1", "score": 0.32, "minutes": 0.7}}`
   - `speakers.json`이 이미 있으면 매칭을 건너뛰고 그 파일을 쓴다. 사용자가 이름을 고친 뒤 재실행하는 경로다.
   - `threshold` 기본값 0.65 (스파이크 결과 참조).

3. merge
   - 같은 클러스터의 인접 구간을 간격 1.0초 이내면 하나의 턴으로 합친다.
   - 0.3초 미만 턴은 버린다. 그 외는 전부 보낸다. (짧은 답변이 회의의 결정을 담는다)
   - 합친 길이가 10분을 넘게 되는 병합은 하지 않는다. (25MB 한도 대비. 스파이크에서 최장 턴이 1.3분이라 실제로는 발동하지 않는 안전장치)

4. transcribe
   - 턴마다 앞뒤 0.2초를 붙여(파일 경계에서 클램프) 16kHz mono 16bit WAV로 메모리에서 잘라 보낸다.
   - 모델 `gpt-transcribe`, `languages=["ko"]`, `keywords` = 사용자 지정 용어 + 매칭된 실명.
   - `AsyncOpenAI`로 8개 병렬. 재시도는 SDK 기본값(`max_retries`).
   - 턴이 끝날 때마다 `out/turns.jsonl`에 한 줄 추가한다:
     `{"i": 12, "speaker": "SPEAKER_00", "start": 754.2, "end": 761.9, "text": "..."}`
   - 시작 시 `turns.jsonl`을 읽어 이미 있는 턴은 건너뛴다. 실패한 턴은 `"text": null`로 기록하고 재실행 시 다시 시도한다.

5. render
   - `out/transcript.md`: `[00:12:34] 홍길동: 텍스트` 한 줄 한 턴.
   - `out/transcript.json`: transcript.md와 같은 병합 행의 배열 (`{"start","end","name","text"}`).
   - 렌더는 항상 `speakers.json`을 다시 읽는다. 같은 이름의 인접 턴은 한 줄로 합친다. 따라서 두 클러스터에 같은 이름을 적으면 자연히 합쳐진다. 빈 텍스트 턴은 출력하지 않는다.
   - `text`가 null인 턴은 `[전사 실패]`로 출력한다.

## 에러 처리

- 시작 시 ffmpeg, HF 토큰, `OPENAI_API_KEY` 부재를 각각 한 줄로 알리고 종료한다.
- `model.txt` 불일치 시 재등록 안내 후 종료한다.
- STT 개별 실패는 파이프라인을 멈추지 않는다. (위 4단계)
- diarization이 클러스터 0개를 내면 종료한다.

## 스파이크 결과 (2026-09-02)

데이터: STT_BMT의 회의 녹음 5개(51~80분, 4~7명)와 클로바노트 출력(실명 + 블록 타임스탬프)을 정답으로 사용.
9명이 회의 3~5개에 걸쳐 등장. 클러스터의 실명은 클로바 블록과 겹친 시간의 다수결로 붙임.

### 1. 속도 (M3 Pro 18GB, pyannote.audio 4.0.7, torch 2.13, MPS)

| 파일 | 길이 | 화자 | 처리 시간 | RTF |
|---|---|---|---|---|
| audio-2 | 51분 | 6 | 192초 | 0.063 |
| audio-1 | 80분 | 5 | 302초 | 0.063 |
| audio-3 | 56분 | 5 | 209초 | 0.062 |
| audio-4 | 66분 | 4 | 245초 | 0.062 |
| audio-5 | 78분 | 7 | 298초 | 0.064 |

MPS로 50분 회의가 약 3분. 모델 로드 첫 회 22초, 이후 2초. CPU 비교는 불필요해 중단. 결정: MPS 기본, 실패 시 CPU 폴백.

### 2. 클러스터 품질 (num_speakers 지정)

- audio-1, 2, 3: 클러스터가 실명과 1:1 대응, 순도 0.77~0.96 (클로바 타임스탬프가 블록 단위라 0.8대가 상한에 가까움).
- audio-4 (4명 지정): 참석자A이 2개 클러스터로 갈라지고, 발화 8블록뿐인 참석자G은 참석자H 클러스터에 흡수됨.
- audio-5 (7명 지정): 43분을 말한 참석자D이 3개로 갈라지고, 발화 6~9블록인 참석자H과 참석자B는 사라짐. 참석자E 클러스터는 순도 0.51로 참석자H과 섞임.
- 결론: 발화량이 극히 적은 사람이 있으면 num_speakers를 맞춰도 지배적 화자가 갈라지고 소수 화자는 흡수된다. 한 사람이 여러 클러스터로 나오는 경우가 정상 상황이며 매칭 단계에서 다대일을 허용해야 한다.

### 3. 세션 간 코사인 유사도 (WeSpeaker centroid, 256차원)

| | n | min | p10 | p50 | p90 | p99 | max |
|---|---|---|---|---|---|---|---|
| 같은 사람 | 39 | 0.704 | 0.738 | 0.908 | | | 0.958 |
| 다른 사람 | 250 | 0.132 | | 0.328 | 0.457 | 0.761 | 0.804 |

다른 사람 상위 4개(0.757~0.804)는 전부 audio-5의 순도 0.51 혼합 클러스터(참석자E+참석자H)와 참석자H의 비교. 이를 빼면 다른 사람 최대는 0.597.
순수 클러스터끼리는 같은 사람 ≥ 0.70, 다른 사람 ≤ 0.60으로 겹치지 않음. 회의실과 온라인이 섞인 녹음에서도 이 간격이 유지됨.

### 4. leave-one-out 매칭 정확도 (DB = 나머지 4개 회의, 사람당 max cos, 클러스터 27개)

| 방식 | 임계값 | 정답 | 오배정 | Unknown |
|---|---|---|---|---|
| 헝가리안 1:1 | 0.5 | 23 | 2 | 2 |
| 헝가리안 1:1 | 0.6 | 23 | 1 | 3 |
| 독립 argmax (다대일 허용) | 0.5~0.7 | 26 | 1 | 0 |

헝가리안의 오배정은 모두 갈라진 클러스터(참석자A 2번째, 참석자D 2·3번째)가 1:1 제약 때문에 엉뚱한 사람에게 밀린 경우.
독립 argmax의 오배정 1건은 순도 0.51 혼합 클러스터로, 배정된 참석자H도 그 클러스터의 절반이라 매칭 오류가 아니라 diarization 오류.


### 5. 턴 병합 시뮬레이션 (exclusive 구간에 병합 규칙 적용)

| 파일 | 원본 구간 | 간격 1초 병합 후 | 0.3초 미만 제외 후 | 1초 미만 턴 | 중앙값 | 최장 턴 | 오디오 총량 |
|---|---|---|---|---|---|---|---|
| audio-2 (51분) | 1172 | 787 | 507 | 148 | 2.4초 | 1.0분 | 45.0분 |
| audio-1 (80분) | 1795 | 1070 | 704 | 183 | 3.1초 | 1.3분 | 70.9분 |
| audio-5 (78분) | 1494 | 938 | 712 | 185 | 2.9초 | 1.0분 | 69.9분 |

- 50분 회의당 STT 호출 약 500회, 오디오 45분, 비용 약 $0.20. 8개 병렬이면 2~3분.
- 0.3초 미만으로 버려지는 턴이 36%지만 합쳐도 1~2분 미만이라 내용 손실은 없다.
- 긴 독백도 다른 사람의 짧은 추임새가 exclusive 구간을 끊어서 최장 턴이 1분 남짓이다. 10분 상한 분할 규칙은 사실상 발동하지 않지만 안전장치로 유지한다.
- 턴 중앙값이 2~3초로 짧아 gpt-transcribe가 받는 문맥이 적다. 클로바 대비 CER이 나쁘면 `prompt`에 직전 턴 텍스트를 넣는 방식을 검토한다. 지금은 넣지 않는다.

### 6. 화자 수 자동 추정 (min 2, max 10) vs num_speakers 지정

| 파일 | 실제 | 지정 결과 | 자동 결과 |
|---|---|---|---|
| audio-4 | 4명 | 4개: 참석자A 2분열, 참석자G 흡수(참석자H 순도 0.68) | 5개: 4명 전원 분리(참석자G 순도 0.76), 참석자A 0.7분 조각 1개 |
| audio-5 | 7명 | 7개: 참석자D 3분열, 참석자H·참석자B 흡수, 참석자E 순도 0.51 | 6개: 6명 분리(참석자D 42.7분 순도 0.97, 참석자E 0.90), 참석자B(9블록)만 흡수 |

자동 추정이 두 파일 모두에서 지정보다 나았다. 사람 수를 강제하면 발화가 적은 사람 자리를 지배적 화자의 조각이 채운다.

자동 추정 결과로 다시 잰 leave-one-out 독립 argmax (임계값 0.5~0.7 동일): 정답 25, 오배정 1, Unknown 1.
- Unknown 1건은 참석자G. audio-4에만 나와 DB에 없으므로 Unknown이 정답이다. 임계값 0.3에서는 참석자F(0.479)에 붙었다. 미등록자를 거르려면 임계값이 0.5 이상이어야 한다.
- 오배정 1건은 audio-4의 0.7분짜리 조각 클러스터. 시간 겹침으로는 참석자A(순도 0.92)이지만 참석자A의 다른 세션과 유사도 0.21, 참석자C과 0.91이다. 클로바가 블록으로 뭉갠 짧은 타인 발화일 가능성이 높다. 1분 미만 클러스터는 신뢰도가 낮으므로 `speakers.json`에 발화 시간을 함께 적어 사용자가 판단하게 한다.
- 이 조각을 빼면 같은 사람 세션 간 유사도 최소는 0.737, 순수 클러스터 기준 다른 사람 최대는 0.583이다.

### 결정

- 매칭: 헝가리안 1:1 대신 클러스터별 독립 argmax + 임계값. 여러 클러스터가 같은 사람에게 붙는 것을 허용하고 렌더 시 합친다. scipy 헝가리안은 쓰지 않는다.
- threshold 기본값 0.65. 같은 사람 최소 0.74와 다른 사람 최대 0.58의 중간이고, 미등록자 거부 하한 0.5보다 여유가 있다.
- 화자 수: transcribe는 자동 추정(min 2, max 10)이 기본. enroll도 자동 추정을 기본으로 하고 `--num-speakers`는 선택.
- `speakers.json`에 클러스터별 발화 시간(분)을 기록한다. 1분 미만은 사용자가 의심하고 볼 수 있게.
- 디바이스: MPS 기본, CPU 폴백.
